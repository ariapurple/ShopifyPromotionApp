# 促銷額度 Requirements

狀態：可以開工。第一版只做「同一條產品，頭 N 件促銷價，賣完返原價」。

相關文件：[design.md](design.md)、[tasks.md](tasks.md)。

## 問題

商家想指定 variant，在一段時間內只讓有限件數用促銷價賣。額度賣完，或時間結束，同一條 listing 繼續以原本 catalog 價出售。

Shopify 原生折扣做不到這件事。折扣使用次數計的是訂單。排程改價會把該 variant 的全部庫存都改成促銷價，而且會改寫 `product.price`。

## 產品決定

- 第一版先做一種活動：促銷額度。資料從第一天就用活動列表，避免之後雙 11 和週年要同時開時再改結構。
- 第一版驗收可以用一個活動完成。同時開兩個活動，放在首頁 banner 那一段。
- 額度按 variant 計。碼數 M 可以有 10 件，碼數 S 可以有 0 件。
- 一個活動裡所有 variant 用同一個折扣百分比。
- 全程不寫入 variant 的 price 或 compare-at price。
- 結帳用 Discount Function，只打折額度內的件數。同一行多出來的件數付原價。
- 接受併發結帳可能多賣 1 至 2 件促銷價。這是公開 app 的平台限制，不是第一版的缺陷待補。
- 百分比是第一版唯一的折扣形式。固定金額留到單貨幣商店的後期，避免多貨幣把「減 50」算成另一種貨幣的 50。

## 角色

- 商家員工：在 Shopify admin 建立、暫停、結束活動，並查看每個 variant 賣了幾多件。
- 網上商店客人：在產品頁看到促銷價和剩餘件數，在結帳只為額度內的件數付促銷價。
- 店內 POS 員工：Discount Function 不能按渠道關閉，所以 POS 單會使用同一個額度。

## 第一版範圍

### 活動

- 商家選擇最多約 100 個 variant。超過 Function 能讀的 10KB 設定時，儲存必須失敗並說明原因。
- 每個 variant 有自己的額度 N，N 是正整數。
- 活動時間只用商店的 IANA 時區。一個活動可以有一段或兩段時期。員工想對齊另一個地方的午夜時，自己換算成商店時間再填第二段。App 不做每個市場各自的午夜。
- 折扣是一個百分比，大於 0、小於或等於 100。
- 商家可以暫停和恢復。暫停後新結帳不再打折。
- 全部 variant 剩餘件數到 0，活動結束，新結帳不再打折。
- 卸載 app 不修改任何產品價錢。

### 結帳

- 購物車某 variant 剩餘 r 件，客人買 q 件：打折件數是 min(q, r)。其餘 q - min(q, r) 付 catalog 價。
- 剩餘是 0、活動暫停、或不在時段內：這件貨完全不打折。
- 結帳顯示的折扣名稱用商家填的活動名稱。
- 促銷只保證網上結帳和會跑 Discount Function 的 POS 結帳。員工在後台手動改單，不會重算額度。

### 產品頁

- 有剩餘件數時，產品頁顯示促銷價、原本 catalog 價，以及「促銷價尚餘 X 件」。
- 客人切換 variant，顯示跟著變。
- 剩餘是 0 或活動不是進行中：不顯示促銷，頁面維持主題原本的價錢。
- 支援方式是主題 app block。商家要在產品模板加一次。第一版不自動改寫每個主題的價錢 HTML。

### 帳目

- 訂單建立後，按該張單實際打折的件數減少剩餘。
- 同一張單重複收到 webhook，不會減兩次。
- 第一版退款不把件數加回額度。

## 明確不做

- 改 catalog 價、compare-at、Google 或 Meta feed 的價錢。
- 保證全球同一秒零超賣。
- 把 POS 排除在額度之外。
- 一個活動裡每個 variant 不同百分比，或固定金額折扣。
- 全店幾千個 variant 一次過。
- 每張單最多打折幾件。這是後期設定。
- 只在指定市場生效。
- 買 A 折扣 B、加 A 之後彈窗、買 A 自動加 B。見下方後期。
- 排程把全部庫存改價、Bundles、預購、B2B 補貨日程。
- App Store 收費。本地和開發商店先跑通；上架前先加 billing。

## 第一版之後第一個行銷功能

結帳跑通之後就做。不另開 app。

同一個首頁 block 可以同時顯示多過一張 banner。例如雙 11 和店慶週年一起出現，各自連去自己的集合。商家不用為每個活動再加 block。

一次過的商家設定：

- 主題是 Online Store 2.0。
- 商家在首頁模板加一次 banner app block，之後留在那裡。
- 每個活動各自選定一個已存在的手動集合。App 不建立集合。

活動有兩類，可以同時進行：

- 促銷額度：指定 variant、有限件數、一個百分比。雙 11 用這一類。
- 集合百分比：商家選一個已有集合，集合內產品無限件數打同一個百分比。週年用這一類。

同一件貨只食一個活動。有促銷額度的 variant 用額度折扣，不再疊週年的百分比。兩個促銷額度不能包含同一個 variant，儲存時要拒絕。兩個集合百分比都命中時，用商家排在前面的那個。

App 負責：

- 每張進行中的 banner 按商家排序，由上至下顯示在同一個 block。暫停或結束的活動不出現。全部結束時 block 留白。
- 促銷額度活動進行中，把有額度的產品加進它自己的集合。暫停、結束或卸載時只移走今次加入的產品。
- 集合百分比活動不改集合成員，banner 直接連去商家選定的集合。
- 圖片用 Shopify Files 儲存。

已知結果要寫進介面：

- 集合顯示的是產品，不是單一 variant。只得某個碼數有額度時，整件產品仍會出現。
- 主題原本的集合產品卡顯示 catalog 價。促銷價和剩餘件數在產品頁的 app block。
- 所有活動共用一份 10KB 設定。空間不夠時拒絕再加活動。

## 後期，仍然是這隻 app

按這個次序加，不另開 app：

1. 每張單上限：全店剩餘和每單上限取較小值。
2. 分市場：建立折扣時用市場資格。其他市場不打折。
3. 退款回補：商家可以選擇退貨件數返回額度。
4. 單貨幣商店的固定金額折扣。
5. 買 A、B 打折或免費。Function 只負責價錢。B 必須已經在購物車。
6. 產品頁彈窗問客人要不要 B。
7. 買 A 送 B：店面程式自動把 B 加進購物車，刪走 A 時一併刪走 B。
8. 歐洲 30 日最低價顯示。

買 A 送 B 的限制要保持：只覆蓋裝了 app block 的網上商店主題。POS、Shop app、headless 不會自動加件。

## 驗收

第一版完成時，開發商店要能示範：

1. 一個 variant 額度 5 件、8 折。買 2 件，訂單裡 2 件都是 8 折，剩餘變 3。產品頁顯示尚餘 3 件。
2. 剩餘 2 件時買 5 件。訂單裡 2 件 8 折、3 件原價。剩餘變 0 之後，新結帳不再打折。
3. 暫停期間加進購物車的件數是原價。恢復後再次打折，直到額度用完或時間結束。
4. 卸載 app 之後，variant 的 price 和 compare-at 與安裝前一致。
5. 設定超過約 100 個 variant 或 10KB 時，不能儲存成一個會讓 Function 讀到空白的活動。

## 已知限制，必須寫進 app 介面

- 兩張單同一秒結帳，可能多賣 1 至 2 件促銷價。
- POS 單計入同一個額度。
- 產品 feed 不會出現促銷價。
- 後台手動單和訂單修改不算進第一版保證。
- 商店最多 25 個進行中的自動折扣。這隻 app 只用 1 個。若建立失敗，要告訴商家是名額問題。
